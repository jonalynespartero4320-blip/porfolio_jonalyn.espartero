Technical Terms and Users Guide

Document Type: Updated Glossary, Role Guide, and Process Reference

This guide explains the current users, roles, terms, permissions, and process words used in the ID & Queuing System. It was updated to match the newer workflow of masterlist setup, PDL management, visitor registration, verified visitor handling, ID issuance, queue admission, special cases, reports, and account administration.

1. User Roles and Access

User Type Meaning Current Typical Access
Staff Frontline user who handles daily visitor operations based on assigned permissions. Dashboard, Visitor Registration, Queue, selected Reports, and other actions granted by the permission matrix.
Admin Operational supervisor who manages records, verification, queueing, ID issuance, and reports. PDL Management, Visitor Management, ID Issuance, Queue Monitor, Reports, Masterlist, and other approved module actions.
Super Admin Governance-level user who controls users, permissions, reset approvals, and protected pages. All modules, Manage Users, permission assignment, reset approvals, and protected pages such as Special Cases.

2. Permission Terms

TermMeaning
ViewAllows a user to open a page, read a table, or inspect a record.
CreateAllows a user to add a new record such as a PDL, queue request, visitor registration, or masterlist item.
EditAllows a user to update an existing record, such as PDL information, visitor details, or masterlist values.
DeleteAllows a user to remove records that are permitted to be deleted by the module.
ImportAllows a user to upload CSV-based records such as PDL lists or authorized visitor lists.
ExportAllows a user to download report outputs such as Excel or PDF files.
PrintAllows a user to open print layouts such as PVC or A4 ID print views and printable reports.
AllGrants the full set of configured actions for the selected module.
Important: If an action button is hidden, disabled, or missing, the user may not have the required permission. The super admin should review the user role and permission matrix first.

3. Core Record Terms

TermSimple Explanation
PDLPerson Deprived of Liberty. The detained person or inmate being visited.
PDL ManagementThe module used to add, edit, import, and maintain PDL records and their linked authorized visitors.
Authorized VisitorA person linked to a selected PDL and allowed to continue into the registration process.
Verified VisitorA registered visitor whose record already passed the registration stage and is available in Visitor Management, ID Issuance, and Queue.
Visitor RegistrationThe process of capturing visitor profile details, photo, emergency contact, valid ID details, and supporting requirements.
Visitor ManagementThe module used to review verified visitors, inspect documents, edit selected details, ban or lift bans, and route visitors to queue or ID issuance.
Accepted IDA valid ID type maintained in Masterlist and used when recording the visitor's valid ID document.
RequirementA document requirement such as Valid ID, Birth Certificate, Marriage Certificate, or Cohabitation Certificate.
MasterlistThe collection of reference lists used by forms and reports, such as Case, Court, Dorm, Relationship, Requirement, and Accepted ID.
DormThe custodial location or assigned area of a PDL, used in records, queue details, and reports.
RelationshipThe visitor's relationship to the PDL, such as spouse, parent, sibling, or other accepted relation.
Emergency ContactThe contact person and contact details recorded for the visitor during registration.

4. ID and Document Terms

TermMeaning
V-IDThe visitor identification number generated by the system.
QR CodeThe scannable code tied to the issued visitor ID and used for queue lookup and admission control.
ID IssuanceThe module used to issue or re-issue the visitor's QR-enabled identification card.
Issue IDThe action used when a verified visitor is receiving an ID for the first time.
Re-IssueThe action used when a visitor already had an ID and a replacement card must be generated again.
Print PVCThe print view for card-sized physical PVC output.
Export A4 PDFThe action used to generate a PDF version of the visitor ID in A4 layout.
Issuance HistoryThe record of previous ID issuance and re-issuance actions for a visitor.

5. Queue and Admission Terms

TermMeaning
QueueThe admission module where a verified visitor is loaded by QR or V-ID and placed into the active waiting line.
Manual SearchThe queue option that lets the user type the V-ID or QR token instead of scanning.
Put in QueueThe action used to submit the loaded visitor into the admission queue.
ApproveThe action used to accept a waiting visitor and allow time in.
RejectThe action used to deny a queue request.
Time InThe recorded timestamp when the visitor is accepted and allowed inside.
Time OutThe recorded timestamp when the visitor leaves and the visit is completed.
Hours StayedThe readable duration computed between time in and time out.
Queue BoardThe visitor-facing display board used for public queue visibility.
Queue MonitorThe admin-facing live monitor showing queue status, waiting count, inside count, completed visits, and rejection-related metrics.
WaitingA queue request that has been submitted but not yet accepted or rejected.
InsideA visitor who has already been admitted and has an active visit inside the facility.
CompletedA visitor record with finished time out.

6. Special Case Terms

TermMeaning
Special CasesA protected page below Queue in the sidebar, accessible only to super admin.
Add Special CaseThe action used to manually encode and approve an exceptional visitor visit.
Approved ByThe approving authority name recorded on a special case entry.
Approved DateThe approval date recorded before a special case can proceed.
Special Case RegisterThe tracking table that shows all special case entries and their queue lifecycle.
Special Case StatusThe stage of a special case entry, such as approved, queued, inside, completed, or rejected.

7. Control and Compliance Terms

TermMeaning
Banned VisitorA visitor who is blocked from admission because of a recorded violation or administrative reason.
Lift BanThe action used by an authorized user to remove an active visitor ban.
Ban HistoryThe record of previous visitor bans, the approving or lifting users, and the dates involved.
Pending UserA newly created or newly reviewed user account that still needs approval, role assignment, or permission confirmation.
Password Reset RequestA request submitted by a user who cannot access the account and needs administrator-issued password recovery.
Approve ResetThe admin action that approves a pending password reset request.
Reject ResetThe admin action that declines a pending password reset request.
Permission MatrixThe permission table where super admin grants View, Create, Edit, Delete, Import, Export, Print, and other allowed actions per module.
Activity LogThe stored history of actions such as login, registration, update, approval, export, and deletion events.

8. Queue and Admission Rules

RuleMeaning
One visit per dayA visitor should not complete multiple visit cycles in the same day using the same identity record unless the workflow explicitly allows otherwise.
Maximum 10 insideOnly ten visitors may be admitted inside at the same time. Another visitor may be approved after a current visitor times out.
Verified records firstRegular queue admissions should come from verified visitor records before queueing is allowed.
Special case is separateExceptional visitor handling is no longer created on the regular queue form and must be processed on the Special Cases page.
Ban blocks queueingA banned visitor should not proceed to normal queueing until the ban is lifted by an authorized action.

9. Reporting Terms

TermMeaning
Report SourceThe category of data being reported, such as Admissions, Registrations, ID Issuance, Banned Visitors, or Special Cases.
Daily ReportShows records for one selected day.
Monthly ReportShows records within a selected month and year.
Yearly ReportShows records within a selected year.
Custom RangeShows records between a selected start date and end date.
Dorm FilterLimits report results to one dorm or dorm-related records.
PDL FilterLimits report results to one selected PDL.
Gender FilterLimits results by applicable gender field.
Custom ColumnsThe report fields chosen by the user for display and export.
Custom HeadersUser-defined column titles used in the exported report output.
Run ReportThe action used to apply filters and generate the report view.
Export ExcelThe action used to download the report in spreadsheet format.
PDF ReportThe printable or PDF-exportable report output.
