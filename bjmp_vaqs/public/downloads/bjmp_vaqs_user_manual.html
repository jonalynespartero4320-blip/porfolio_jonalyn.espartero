Step-by-Step User Manual

User Manual

Document Type: Daily Operating Guide

This manual explains the step-by-step process of using the ID & Queuing System. It is written as a plain instruction guide so staff, admin, and super admin users can follow the actual workflow from login up to reporting and account administration.

Recommended daily sequence: Sign in, check the masterlist references, prepare PDL records, attach authorized visitors, register visitors, review verified visitor records, issue IDs when needed, process queue admission, handle special cases if approved, generate reports, and review user or reset requests when authorized.

1. Accessing the System

1.1 Sign In

  1. Open the ID & Queuing System login page.
  2. Enter your username.
  3. Enter your password.
  4. Sign in to open the system dashboard.

1.2 Request a Password Reset

  1. Open the reset request page from the login screen.
  2. Enter your username.
  3. Submit the reset request.
  4. Wait for admin or super admin approval before signing in again.

2. Prepare Masterlist References

Before encoding live records, make sure the system references are complete. These references include Case, Court, Dorm, Relationship, Requirement, and Accepted ID.

  1. Open the Masterlist module.
  2. Select the reference tab that needs to be updated.
  3. Add the missing reference if it does not yet exist.
  4. Enter the name or description of the reference.
  5. Save the new entry.
  6. Search the table and confirm the entry appears correctly.

3. PDL Management

3.1 Add a PDL Record Manually

  1. Open PDL Management.
  2. Create a new PDL record.
  3. Enter the PDL details, including name, age, sex, dorm, case number, case type, and court.
  4. Enter the authorized visitors linked to that PDL.
  5. Review the information for accuracy.
  6. Save the PDL record.

3.2 Import PDL Records by CSV

  1. Open the PDL import page.
  2. Download the CSV template.
  3. Fill in the PDL records in the template.
  4. Save the completed template as a CSV file.
  5. Return to the system and choose the completed file.
  6. Start the import process.
  7. Wait for the completion message and review the result summary.

3.3 Add or Import Authorized Visitors Under a PDL

  1. Find the target PDL in the PDL list.
  2. Open the visitor list for that PDL.
  3. If you are adding visitors one by one, enter their details directly in the visitor section.
  4. If you are importing visitors in bulk, open the import page for that PDL.
  5. Download the visitor template and complete the visitor details.
  6. Upload the completed visitor file.
  7. Review the imported or encoded visitor list and confirm the correct visitors are linked to the selected PDL.

4. Visitor Registration

This process converts an authorized visitor into a verified visitor record that can later be used for ID issuance and queue admission.

  1. Open Visitor Registration.
  2. Select the PDL group based on male or female records.
  3. Select the PDL to be visited.
  4. Load the authorized visitors linked to that PDL.
  5. Choose the correct visitor from the authorized list.
  6. If the visitor is new to the form, start the registration process.
  7. If the visitor already has unfinished data, continue the registration process from the saved stage.
  8. Review the auto-filled visitor information.
  9. Capture or upload the visitor photo.
  10. Confirm the photo and continue to the next registration stage.
  11. Enter the emergency contact information.
  12. Save the visitor details stage.
  13. Upload the required supporting documents.
  14. Review each document before final upload confirmation.
  15. Confirm each uploaded document.
  16. Submit the completed registration.
Result: After submission, the visitor becomes part of the verified visitor records and can be used in Visitor Management, ID Issuance, and Queue.

5. Verified Visitor Management

  1. Open Visitor Management.
  2. Use the search and filter tools to find the correct visitor record.
  3. Open the visitor details to review personal information, PDL linkage, photo, and uploaded documents.
  4. Edit the visitor record if corrections are needed.
  5. Update the emergency contact if the information must be changed.
  6. Update a requirement file if a new document must replace the old one.
  7. Send the visitor to queue when the record is ready for admission.
  8. Open the ID workflow if the visitor needs an ID card.
  9. Ban the visitor if a restriction must be applied.
  10. Lift the ban only when the restriction is officially cleared.
  11. Check ban history if you need to review previous restrictions.

6. ID Issuance

  1. Open the ID Issuance module.
  2. Select the male or female PDL tab.
  3. Select the PDL whose verified visitors need IDs.
  4. Review the verified visitors shown under that PDL.
  5. Issue an ID if the visitor does not yet have one.
  6. Re-issue the ID if the visitor already had one and a replacement is required.
  7. Open the visitor card preview page.
  8. Print the PVC card if physical card printing is needed.
  9. Export the A4 PDF if a PDF copy is needed.
  10. Review issuance history if you need to trace prior issuance actions.

7. Queue Admission and Time In / Time Out

  1. Open the Queue module.
  2. Load the visitor by scanning the QR code or by typing the V-ID or QR token manually.
  3. Review the visitor details shown on the screen.
  4. Place the visitor into the active queue.
  5. Confirm the queue entry when required.
  6. Wait for the queue request to appear in the request table.
  7. Approve the request to admit the visitor, or reject it if the visitor cannot proceed.
  8. When the visit is finished, record time out from the queue workflow.
  9. Use the queue monitor when an admin view of the live queue is needed.
  10. Use the visitor board when a public queue display is needed.
Important queue rule: Time in and time out should always be completed inside the same queue workflow so that reports remain accurate.

8. Special Cases

This process is separate from the regular queue page and is protected for super admin access.

  1. Open the Special Cases page.
  2. Create a new special case entry.
  3. Enter the visitor identity details.
  4. Enter the linked PDL name, dorm, and visit reason.
  5. Enter the approval details, including approving person and approval date.
  6. Approve the special case entry.
  7. Monitor the special case record in the special case register as it moves through queued, inside, completed, or rejected states.

9. Reports

  1. Open the Reports module.
  2. Select the report source, such as Admissions, Registrations, ID Issuance, Banned Visitors, or Special Cases.
  3. Select the reporting period, such as daily, monthly, yearly, or custom range.
  4. Apply the available filters such as year, month, date range, dorm, PDL, gender, or ban status.
  5. Choose custom report columns if needed.
  6. Rename report headers if a custom export layout is required.
  7. Run the report.
  8. Review the summary cards, charts, and table output.
  9. Reset the filters when you want to clear the current report setup.
  10. Export the report to Excel or create the PDF or print output if needed.

10. User Administration and Reset Requests

This part applies only to users who are allowed to manage accounts and permissions.

  1. Open the user administration page.
  2. Review the user list and account status.
  3. Search for a user when a specific account must be updated.
  4. Adjust the role and permission settings of the user if needed.
  5. Save the permission changes after review.
  6. Open the reset requests section to review pending password recovery requests.
  7. Approve the request if the reset is valid, or reject it if the request should not proceed.

11. Role Guide

Role Main Use of the System
Staff Performs frontline registration, visitor handling, queue intake, and other daily actions based on assigned permissions.
Admin Supervises records, visitor verification, queue processing, ID issuance, and reports.
Super Admin Controls user governance, reset approvals, permission assignment, and access to protected pages such as Special Cases.
